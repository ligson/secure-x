# 加密文件分享与聊天大文件

本文说明 Secure X 中“文件模块分享”和“聊天大文件发送”的实现边界。

## 设计目标

- 聊天消息只保存轻量文件引用，不承载大文件内容。
- 文件内容始终先在客户端加密，再以密文分片上传到服务端。
- 服务端只保存密文文件、密文元数据和最小下载授权，不持有文件密钥、文件名明文或聊天正文。
- 分享给好友或群聊后，接收方只能在聊天端到端加密消息中拿到文件引用和解密参数。
- 非授权用户即使知道文件 ID，也不能从服务端下载密文文件。

## 聊天大文件发送

聊天窗口里的普通文件和视频不再走旧的聊天附件整体上传通道，而是复用文件模块的加密分片上传链路：

1. 客户端选择本地文件时不把完整文件读入内存。
2. 客户端按固定大小读取明文分片。
3. 每个分片在客户端用随机文件密钥加密。
4. 密文分片上传到服务端上传会话。
5. 上传完成后，服务端合并密文文件。
6. 客户端发送一条聊天消息，消息内只包含端到端加密后的文件引用：
   - 文件 ID
   - 文件密钥
   - 文件名
   - MIME 类型
   - 原始大小
   - 分片密文大小列表

上述引用字段位于聊天端到端加密 payload 内，服务端不能读取明文引用内容，也不能得到文件密钥。

## 文件模块分享

文件模块中文件右侧菜单提供“分享”入口，可以选择好友或群聊。

分享已有文件时不会重新上传文件内容：

1. 客户端请求服务端把目标好友或群成员追加到该密文文件的下载授权列表。
2. 服务端校验分享者是文件 owner。
3. 服务端校验目标用户与分享者存在好友或实时通讯权限。
4. 客户端向对应会话发送一条端到端加密的文件引用消息。
5. 分享完成后打开对应会话，可以看到该文件引用。

服务端的授权列表只控制“谁可以下载密文文件”，不包含文件密钥，也不代表保险库授权。好友关系本身仍不允许对方读取用户的密码库或文件库。

## 下载与解密

接收方点击聊天中的文件引用保存时：

1. 客户端向服务端请求下载密文文件流。
2. 服务端只在用户被授权时返回密文流。
3. 客户端按文件引用中的分片密文大小切分密文流。
4. 每个密文分片在客户端解密后写入本地文件。

大文件下载不需要把完整明文文件放入聊天消息或聊天缓存。

## 断点续传边界

当前上传任务运行期间支持分片级续传：

- 上传某个分片失败后，客户端会查询服务端已上传分片列表。
- 已存在的分片会被跳过。
- 缺失分片会继续上传。
- 重新上传仍使用原上传会话和原文件密钥。

当前版本尚未持久化上传会话到本地，因此 App 被系统杀掉、用户退出应用或设备重启后的跨进程续传仍是后续增强项。要支持完整跨重启续传，需要安全保存上传 ID、文件路径、文件密钥、分片状态和目标授权信息，并处理移动端文件访问权限恢复问题。

## 安全边界

- 服务端不得记录文件密钥、聊天引用明文、token、密文 payload 或生产部署信息。
- 分享授权只允许文件 owner 追加。
- 目标用户必须与 owner 有好友或共同群成员实时通讯权限。
- 群聊分享只授权当前群成员；后续群成员变更不自动追溯修改旧文件授权。
- 删除好友不等价于自动撤销历史文件授权；后续如需支持撤销，需要增加显式授权管理和密钥轮换设计。
