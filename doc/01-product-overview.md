# 产品概览

## 1. 项目愿景

Secure X 旨在提供一个“以客户端加密为核心”的敏感信息管理系统。用户可以像使用密码管理器一样管理登录信息，同时还可以上传和维护加密文件，服务端只承担认证、同步与密文存储职责。

## 2. 目标用户

- 对个人账号、密钥、文档有集中管理需求的个人用户
- 需要私有部署、可控后端地址的小团队
- 希望同时管理密码条目与敏感附件的用户

## 3. 产品边界

本阶段明确包含：

- 账户注册与登录
- 客户端配置后端地址
- 解锁密码驱动的本地加密体系
- 密码库分类管理
- 密码/登录信息管理
- 网盘式加密文件目录管理
- 加密文件上传下载管理
- 好友通讯录与好友申请管理
- 好友加密聊天会话
- 随机密码生成器
- 多端同步基础能力

本阶段明确不包含：

- Web 端
- 浏览器自动填充
- 团队共享保险库
- SSO、企业目录集成
- 在线文档编辑

## 4. 核心功能设计

### 4.1 账户体系

- 用户可注册账号
- 用户可登录账号
- 用户可修改服务端登录密码
- 用户可修改解锁密码，客户端重新封装保险库密钥后同步密文配置
- 用户在客户端设置解锁密码
- 解锁密码不应以明文形式发送到服务端
- 修改登录密码不应影响解锁密码、保险库密钥或已加密业务数据

### 4.2 信息库管理

- 支持建立密码库分类
- 支持集中管理密码库分类，包括新增、修改与删除
- 删除分类前需要判断分类下是否还有密码项或子分类，有则提示用户先处理
- 支持在分类下管理密码/登录条目
- 条目类型至少包括：
  - 登录信息
  - 安全备注

文件不复用密码库分类，文件模块单独按网盘目录组织。

### 4.3 登录信息条目

建议字段：

- 标题
- 用户名
- 密码
- 网站或应用地址
- 备注
- 标签
- 创建时间与更新时间

### 4.4 加密文件

- 支持上传任意文件
- 支持建立文件目录与进入/返回目录
- 文件在上传前由客户端完成加密
- 文件目录名、文件名、文件密钥等业务元数据同样由客户端加密
- 服务端保存密文文件与必要结构元数据
- 下载后由客户端完成解密再供用户使用

### 4.5 密码生成器

建议支持：

- 长度配置
- 大小写字母
- 数字
- 特殊字符
- 避免易混淆字符

### 4.6 好友通讯录

- 支持通过准确的用户名或邮箱发送好友申请
- 好友申请必须由对方同意后才建立关系
- 支持查看好友列表、好友详情与删除好友
- 好友关系只用于通讯录和后续协作入口，不自动授予密码库、文件库或密文资源访问权限
- 即使成为好友，对方也不能读取、下载或解密自己的密码、文件和其他保险库数据

### 4.7 加密聊天

- 底部主导航在 `文件` 与 `好友` 之间提供 `聊天`
- 聊天页展示与好友的会话列表，好友详情页可直接发起聊天
- 聊天页右上角提供 `发起群聊` 与 `添加好友`；发起群聊选择 1 个好友时进入单聊，选择多个好友时需要填写群聊名称
- 消息设计为端到端加密实时传输，优先采用 WebRTC 数据通道或等价的 P2P 加密通道
- 服务端只提供在线发现、信令配置或转发必要的握手信息，不保存聊天消息正文
- 好友离线或实时通道不可用时，待发消息只加密保存在发送方本机，不上传服务端排队
- 用户登录解锁后会向在线好友或共同群成员发起端到端历史同步，把对方本机已有的单聊/群聊历史合并到当前客户端
- 群聊消息按成员逐个端到端发送，群会话与消息只在客户端本机加密保存；服务端不保存群消息、不保存群会话密钥
- 群主为第一个创建群聊的用户，可移除群成员；普通成员可邀请自己的好友进群
- 群成员可在群设置中退出群聊，退出前需要确认，退出后删除本机该群聊天记录；群主退出时自动把下一位成员升级为群主
- 客户端需要实时服务地址时，必须通过 HTTP 配置接口获取，不能硬编码 socket 端口

## 5. MVP 设计原则

- 优先把个人密码库和加密文件库打通
- 优先保证安全边界清晰，再逐步优化体验
- 优先保证桌面与移动端共享一套主要业务逻辑
- 优先支持自部署单实例

## 6. 非功能目标

- 安全优先
- 结构简单，便于私有部署
- 同步机制可维护
- 后续具备横向扩展与对象存储迁移空间
