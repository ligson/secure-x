# 产品概览

## 1. 项目愿景

Secure X 旨在提供一个“以客户端加密为核心”的敏感信息管理系统。用户可以像使用密码管理器一样管理登录信息，同时还可以上传和维护加密文件，服务端只承担认证、同步与密文存储职责。

## 2. 目标用户

- 对个人账号、密钥、文档有集中管理需求的个人用户
- 需要私有部署、可控后端地址的小团队
- 希望同时管理密码条目与敏感附件的用户

## 3. 产品边界

本阶段明确包含：

- 账户注册与登录
- 客户端配置后端地址
- 解锁密码驱动的本地加密体系
- 密码库分类管理
- 密码/登录信息管理
- 网盘式加密文件目录管理
- 加密文件上传下载管理
- 随机密码生成器
- 多端同步基础能力

本阶段明确不包含：

- Web 端
- 浏览器自动填充
- 团队共享保险库
- SSO、企业目录集成
- 在线文档编辑

## 4. 核心功能设计

### 4.1 账户体系

- 用户可注册账号
- 用户可登录账号
- 用户可修改服务端登录密码
- 用户可修改解锁密码，客户端重新封装保险库密钥后同步密文配置
- 用户在客户端设置解锁密码
- 解锁密码不应以明文形式发送到服务端
- 修改登录密码不应影响解锁密码、保险库密钥或已加密业务数据

### 4.2 信息库管理

- 支持建立密码库分类
- 支持集中管理密码库分类，包括新增、修改与删除
- 删除分类前需要判断分类下是否还有密码项或子分类，有则提示用户先处理
- 支持在分类下管理密码/登录条目
- 条目类型至少包括：
  - 登录信息
  - 安全备注

文件不复用密码库分类，文件模块单独按网盘目录组织。

### 4.3 登录信息条目

建议字段：

- 标题
- 用户名
- 密码
- 网站或应用地址
- 备注
- 标签
- 创建时间与更新时间

### 4.4 加密文件

- 支持上传任意文件
- 支持建立文件目录与进入/返回目录
- 文件在上传前由客户端完成加密
- 文件目录名、文件名、文件密钥等业务元数据同样由客户端加密
- 服务端保存密文文件与必要结构元数据
- 下载后由客户端完成解密再供用户使用

### 4.5 密码生成器

建议支持：

- 长度配置
- 大小写字母
- 数字
- 特殊字符
- 避免易混淆字符

## 5. MVP 设计原则

- 优先把个人密码库和加密文件库打通
- 优先保证安全边界清晰，再逐步优化体验
- 优先保证桌面与移动端共享一套主要业务逻辑
- 优先支持自部署单实例

## 6. 非功能目标

- 安全优先
- 结构简单，便于私有部署
- 同步机制可维护
- 后续具备横向扩展与对象存储迁移空间
