# 迭代路线图

## 1. 阶段划分

### 阶段 A：设计冻结

目标：

- 明确产品范围
- 明确架构边界
- 明确加密模型
- 明确仓库结构与协作规则

交付物：

- `README.md`
- `AGENTS.md`
- `doc/` 设计文档
- `CHANGELOG.md`

### 阶段 B：基础脚手架

目标：

- 初始化 Go 服务端工程
- 初始化 Flutter 多端工程
- 建立基础目录结构与构建命令
- 接入本地数据库与配置体系

### 阶段 C：认证与本地加密

目标：

- 注册与登录流程
- 主密码输入与密钥派生
- 本地加密存储打通
- 后端地址配置打通

### 阶段 D：密码库 MVP

目标：

- 文件夹管理
- 登录信息条目增删改查
- 随机密码生成器
- 基础同步

### 阶段 E：加密文件 MVP

目标：

- 文件上传下载
- 文件分块加密
- 文件索引与同步

### 阶段 F：体验与安全增强

目标：

- 应用锁定
- 生物识别解锁
- 冲突处理
- 审计日志
- 备份与迁移

## 2. 建议优先级

优先做：

- 文档
- 工程结构
- 认证
- 本地加密
- 密码条目
- 文件能力

稍后做：

- 搜索优化
- 文件预览
- 分享与团队空间
- 对象存储抽象

## 3. 当前建议的下一步

如果你确认这套方案方向没问题，下一轮建议进入以下工作：

1. 冻结首版产品边界与术语
2. 设计详细数据模型与 API 草案
3. 初始化 Go 与 Flutter 工程脚手架
4. 先打通注册、登录、主密码与本地加密闭环
