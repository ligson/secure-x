# 迭代路线图

## 1. 阶段划分

### 阶段 A：设计冻结

目标：

- 明确产品范围
- 明确架构边界
- 明确加密模型
- 明确仓库结构与协作规则

交付物：

- `README.md`
- `AGENTS.md`
- `doc/` 设计文档
- `CHANGELOG.md`

### 阶段 B：基础脚手架

目标：

- 初始化 `securex-be/` Go 服务端工程
- 初始化 `securex-app/` Flutter 多端工程
- 建立基础目录结构与构建命令
- 接入本地数据库与配置体系

### 阶段 C：认证与本地加密

目标：

- 注册与登录流程
- 登录密码修改
- 解锁密码输入与密钥派生
- 本地加密存储打通
- 后端地址配置打通

### 阶段 D：密码库 MVP

目标：

- 密码库分类管理
- 登录信息条目增删改查
- 随机密码生成器
- 基础同步

### 阶段 E：加密文件 MVP

目标：

- 文件上传下载
- 网盘式文件目录
- 文件分块加密与后台上传进度
- 文件索引与同步

### 阶段 F：体验与安全增强

目标：

- 应用锁定
- 生物识别解锁
- 上传任务重启后自动断点恢复
- 冲突处理
- 审计日志
- 备份与迁移

## 2. 建议优先级

优先做：

- 文档
- 工程结构
- 认证
- 本地加密
- 密码条目
- 文件能力

稍后做：

- 搜索优化
- 文件预览
- 分享与团队空间
- 对象存储抽象

## 3. 当前建议的下一步

当前基线实现已经完成 `securex-be/` 与 `securex-app/` 的第一版骨架。下一轮建议进入以下工作：

1. 补齐密码分类、登录项、文件目录、文件的编辑与删除交互
2. 增强同步策略与版本冲突提示
3. 把密码分类与文件目录的层级、搜索与筛选体验补完整
4. 评估把主密钥派生从 `PBKDF2-SHA256` 升级到 `Argon2id`
5. 增加更多自动化测试与跨平台打包验证
